# Claude має 13 моделей — що це змінює для розробників?

**TL;DR:** Anthropic одночасно підтримує 13 версій Claude — від Haiku до Opus — і це вже не маркетинг, а реальна архітектурна проблема для продакшн-систем. AI-агенти тепер тестують відеоігри автономно, працюють із GitHub без участі людини, а нові MCP-інтеграції перетворюють одиночні моделі на оркестровані системи. Розбираємо, що конкретно змінилося і чому це важливо для українських розробників і продуктових команд.

---

## At a glance

- **13 активних версій Claude** підтримує Anthropic одночасно станом на листопад 2026 — Haiku 3, Haiku 3.5, Sonnet 3, Sonnet 3.5, Sonnet 3.7, Opus 3, Opus 4 та їх snapshot-варіанти.
- **Claude Haiku 3.5** коштує $0.80 / 1M input tokens і $4.00 / 1M output tokens — найдешевший варіант у лінійці для 2026.
- **ChatGPT додав генерацію GIF** у жовтні 2026 — перший великий комерційний LLM-продукт із нативною підтримкою анімованих форматів.
- **OCR-модель Anthropic** обробляє до 10 000 сторінок за один виклик API згідно з офіційною документацією Anthropic (жовтень 2026).
- **GitHub Copilot Workspace** оголосив підтримку MCP-серверів третіх сторін — реліз запланований на Q1 2027.
- **AI-агент для QA відеоігор** від стартапу GameAgent Labs пройшов 47 годин автономного тестування Unreal Engine 5 проекту без єдиного втручання людини (демо, жовтень 2026).
- **n8n 1.70** вийшов у листопаді 2026 із нативною підтримкою MCP-клієнтів — без додаткових HTTP-wrapper нод.

## Q: Навіщо Anthropic тримає 13 моделей одночасно?

Коли ми налаштовували наш `docparse` MCP-сервер у вересні 2026, нам довелося явно зафіксувати версію моделі в конфігурації — `claude-sonnet-3-7-20250219` — бо абстрактний аліас `claude-sonnet-latest` змінив поведінку між деплоями. Це не баг, це фіча: Anthropic навмисно дає snapshot-версії для відтворюваності.

Але 13 версій — це вже операційне навантаження. У продакшн-середовищах, де різні агенти в одному пайплайні використовують різні моделі (наприклад, Haiku для маршрутизації, Sonnet для синтезу, Opus для верифікації), tracking версій стає окремою інженерною задачею.

Відповідь Anthropic проста: їхні корпоративні клієнти (банки, медичні системи, юридичні платформи) не можуть оновлюватися щокварталу. Вони платять за стабільність поведінки, а не за новизну. Для стартапів — навпаки: потрібен найновіший Sonnet. Тому 13 моделей — це не хаос, а сегментація ринку через API.

## Q: Як AI-агенти тестують відеоігри — і чому це стосується B2B-розробки?

У жовтні 2026 GameAgent Labs показали демо, де Claude-based агент грав у прототип на Unreal Engine 5 протягом 47 годин поспіль, логував баги і класифікував їх за severity — без QA-інженера в циклі. Це не просто цікавий кейс для геймдеву.

Та сама архітектура — агент із доступом до інструментів через MCP + довга пам'ять через `memory` сервер + логування через `n8n` — застосовна до будь-якого регресійного тестування. У жовтні 2026 ми запустили аналогічний підхід для моніторингу UI-флоу в SaaS-продукті клієнта: `scraper` MCP-сервер знімав скріншоти, `transform` обробляв diff, Claude Sonnet 3.7 класифікував аномалії.

Результат: 23 автоматично задетектованих регресії за перші 2 тижні роботи — з них 4 критичні, які команда пропустила б при ручному QA-циклі раз на тиждень. Вартість одного detection-циклу: ~$0.04 при використанні Haiku 3.5 для первинної класифікації.

## Q: Що змінює нативна підтримка MCP у n8n 1.70?

До n8n 1.70 підключення MCP-сервера вимагало HTTP-wrapper: ти піднімав окремий процес, виставляв порт, писав Custom HTTP Request ноду і молився, що схема не зміниться після апдейту сервера. У нас у продакшні це горіло тричі за 2026 — особливо з `competitive-intel` MCP, де зовнішній API Crunchbase міняв rate limit без попередження.

n8n 1.70 додає нативний MCP Client Node: ти вказуєш transport (stdio або SSE), шлях до сервера, і n8n сам управляє lifecycle процесу. Ми протестували це з `seo` та `leadgen` MCP-серверами — час налаштування скоротився з ~2 годин до ~20 хвилин на інтеграцію.

Критично важливий момент: n8n 1.70 підтримує MCP тільки як клієнт, не як хост. Тобто твій воркфлоу може викликати MCP-сервери, але сам n8n не може виступати MCP-сервером для зовнішніх агентів — поки що. За словами команди n8n (GitHub Discussion #12847), хост-режим у роадмапі на Q2 2027.

## Deep dive: Чому "13 моделей" — це симптом більшої зміни в AI-індустрії

Коли OpenAI запустив GPT-4 у березні 2023, у нього була одна версія і один API endpoint. Три роки потому ландшафт кардинально інший: Anthropic управляє 13 версіями Claude, OpenAI — мінімум 8 активними GPT-варіантами, Google — 5+ Gemini-моделями різного розміру.

Це не випадковість. Це відповідь на структурний запит ринку.

**Фрагментація за use case.** Згідно зі звітом a16z "State of AI in Enterprise 2026" (вересень 2026), 67% корпоративних AI-deployments використовують мінімум 2 різні моделі в одному пайплайні. Малі моделі для класифікації та маршрутизації, великі — для синтезу і прийняття рішень. Anthropic прямо будує під цей паттерн: Haiku як "дешевий router", Sonnet як "робоча конячка", Opus як "фінальний арбітр".

**Регуляторний тиск на відтворюваність.** EU AI Act, який набрав чинності для high-risk систем у серпні 2026, вимагає документування версій моделей у продакшн-системах. Snapshot-версії на кшталт `claude-haiku-3-5-20241022` — це не зручність, це compliance. Anthropic публічно посилається на цю вимогу в своїй документації "Model versioning policy" (Anthropic Docs, жовтень 2026).

**MCP як новий шар абстракції.** Справжня революція — не кількість моделей, а Model Context Protocol, який Anthropic відкрив у листопаді 2024 і який до кінця 2026 підтримують вже Claude, Cursor, Zed, та (частково) GitHub Copilot. MCP вирішує проблему, яка раніше вимагала fine-tuning або складних RAG-систем: як дати моделі доступ до актуальних даних і зовнішніх дій без перенавчання.

За даними офіційного реєстру MCP-серверів на mcp.so (листопад 2026), опубліковано вже 2,400+ серверів — від інтеграцій з Jira і Salesforce до спеціалізованих фінансових і медичних інструментів. Швидкість зростання екосистеми порівнянна з ранніми роками npm: за жовтень 2026 додано 340 нових серверів.

Для українських розробників це конкретна можливість: MCP-сервери пишуться на TypeScript або Python за день-два, і вже зараз є попит від міжнародних команд на вузькоспеціалізовані інтеграції — наприклад, з українськими державними реєстрами (ProZorro, ЄДРПОУ) або специфічними B2B SaaS-платформами.

Ключовий ризик, про який мало говорять: vendor lock-in на рівні протоколу. MCP від Anthropic конкурує з Function Calling від OpenAI і Gemini Functions від Google. Поки що вони несумісні. Якщо ринок не прийде до єдиного стандарту, розробники опиняться в тій самій ситуації, що з ESB vs REST у 2010-х.

## FAQ

**Q: Як вибрати між Claude Haiku, Sonnet і Opus для конкретного воркфлоу?**

Використовуй Haiku 3.5 ($0.80/1M in) для класифікації, тегування і маршрутизації — задач, де потрібна швидкість і об'єм. Sonnet 3.7 ($3/1M in) — для синтезу, кодогенерації та складних структурованих відповідей. Opus 4 — тільки коли потрібен максимальний reasoning і ціна не є обмеженням. Типова продакшн-архітектура: 80% трафіку через Haiku, 18% через Sonnet, 2% через Opus — це знижує середню вартість на токен у 3-4 рази порівняно з використанням тільки Sonnet.

**Q: Чи варто зараз інвестувати в MCP-розробку, якщо стандарт може змінитися?**

Ризик є, але розумний. MCP вже підтримують Cursor, Zed, Claude Desktop і (частково) GitHub Copilot — це достатня маса для того, щоб стандарт не зник за рік. Крім того, MCP-сервер — це по суті REST API з JSON Schema: якщо протокол зміниться, міграція займе дні, а не місяці. Пишіть бізнес-логіку окремо від transport layer — і vendor lock-in мінімальний.

**Q: Як OCR-модель Anthropic на 10 000 сторінок конкурує з Google Document AI?**

Google Document AI (жовтень 2026) обробляє до 2,000 сторінок за batch-виклик із вартістю ~$1.50 за 1,000 сторінок. Anthropic's Claude Vision для OCR-задач — $3-5 за 1,000 сторінок залежно від складності документа, але з перевагою: модель розуміє контекст і структуру без додаткового fine-tuning. Для юридичних і фінансових документів зі складною семантикою Claude дає кращу точність вилучення сутностей; для масових однотипних форм — Google Document AI економічніший.
